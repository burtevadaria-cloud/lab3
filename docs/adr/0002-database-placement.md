# ADR-0002. Размещение базы данных
- Статус: принято
- Дата: 2026-10-17

## Контекст
Для проекта TimeCapsule необходимо выбрать наиболее безопасное и масштабируемое место для размещения базы данных PostgreSQL в инфраструктуре AWS.

## Решение
База данных размещается на отдельном сервере EC2 в приватной подсети внутри VPC.

## Рассмотренные альтернативы
- **На одном сервере с приложением, как в ЛР2**.  
  Плюсы: простота настройки, минимальные задержки сети.  
  Минусы: единая точка отказа, невозможность раздельного масштабирования, при компрометации веб-сервера злоумышленник получает полный доступ к данным.

- **На отдельном сервере в публичной подсети**.  
  Плюсы: легко подключаться для администрирования и скачивать обновления.  
  Минусы: низкий уровень безопасности, наличие публичного IP-адреса делает базу уязвимой для сканирования и атак извне.

- **На отдельном сервере в приватной подсети**.  
  Плюсы: максимальная безопасность, сервер полностью изолирован от интернета, доступ только от веб-сервера и бастиона.  
  Минусы: усложненная архитектура, требующая бастион для SSH и NAT Gateway для скачивания пакетов.

## Последствия
- **Обновления базы данных**: Сервер базы данных не имеет постоянного маршрута в интернет. Для установки пакетов и получения обновлений используется временный NAT Gateway, который поднимается только на период технического обслуживания. Это позволяет сэкономить, избегая фиксированной почасовой платы за постоянно работающий NAT.
- **Elastic IP для app-server**: В текущей архитектуре `app-server` нуждается в Elastic IP, чтобы сохранять неизменный публичный адрес при перезагрузках для доступа пользователей. Когда в архитектуру будет добавлен балансировщик нагрузки, публичная точка входа и статический IP перейдут к нему, а `app-server` больше не будет нуждаться в Elastic IP и может быть перенесен в приватную подсеть.
